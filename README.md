# ИИ агент ГК «Садыхан» для розницы

## Цель
Создать ИИ-систему, которая автоматически анализирует продажи розничной сети, выявляет отклонения, объясняет причины и предлагает решения. Решение объединяет административную панель с доступом к ИИ-агенту и автоматическими сценариями контроля сети.

## Результат для руководства
- **Интеллектуальный аналитический инструмент.** Анализ чековых данных, фиксация просадок выручки, аномальных действий кассиров, резких изменений спроса, нетипичных средних чеков и других событий. К каждой аномалии формируется объяснение и рекомендация.
- **Административная панель.** Веб-интерфейс с показателями сети/городов/аптек, динамикой продаж, эффективностью кассиров, движением SKU и журналом всех отклонений. В панели есть интерфейс GPT с подписью «ГК “Садыхан”» слева и возможность задавать аналитические вопросы (например, «построй гипотезу, почему продажи просели» или «какие аномалии есть?»).
- **Автоматизация контроля сети.** Ежедневная фиксация отклонений: снижение выручки по точкам, всплески возвратов, необычные скидки, нулевые продажи ключевых SKU, смещение пиков продаж и др. Система делает контроль прозрачным и оперативным.
- **Основа для масштабирования.** Заложена архитектура для прогнозов, сравнения план/факт, контроля ассортимента, подключения поставок и логистики, объединения финансовой информации для полного цифрового контура.
- **Экономический эффект.** Снижение потерь, рост прозрачности и ускорение принятия решений: выявление недополученной прибыли, ошибок сотрудников, просадки спроса, неверных операций и упущенных возможностей.

## Основной функциональный охват
- **Аналитика продаж и чеков:** показатели по сети/городам/аптекам, динамика продаж, средний чек, анализ корзины, сезонность.
- **Детектор аномалий:** просадки выручки, всплески возвратов, аномальные скидки, нулевые продажи важных SKU, смещение пиков продаж, ошибки кассиров.
- **Рекомендации:** причины отклонений, приоритеты действий, сценарии исправления (цены, промо, запасы, обучение кассиров).
- **Журнал отклонений:** хронология событий, статус обработки, ответственный, принятые меры.
- **Админ-панель:** дешборды, разрезы данных, мониторинг кассиров и SKU, фильтры по времени и географии, встроенный чат с ИИ-агентом (GPT) с фирменной подписью.
- **Оповещения:** ежедневные дайджесты и push/мессенджер-уведомления об инцидентах и их статусе.

## Архитектурные контуры
- **Источники данных:** кассовые продажи, товары/SKU, скидки и промо, возвраты, расписание смен, справочники точек и персонала.
- **Обработка и хранение:** пайплайн загрузки (ETL/ELT) в витрину, нормализация чеков, хранение исторических срезов и признаков.
- **Модуль аномалий:** правила + статистические/ML методы, формирование карточек инцидентов и причин.
- **LLM-агент:** оркестрация запросов, Retrieval (контекст из витрины и журнала инцидентов), генерация гипотез и рекомендаций, встраивание в панель.
- **Админ-панель:** веб-UI с дешбордами, журналом отклонений, карточками инцидентов, и чат-интерфейсом «ГК “Садыхан”» для аналитических диалогов.
- **Интеграции и алерты:** webhook’и/боты для уведомлений, SLA на доставку и отзывчивость.

## Следующие шаги (MVP)
1. **Сбор данных:** схема чеков, SKU, скидок, возвратов и справочников; загрузка в БД.
2. **Базовые метрики и витрина:** расчёт выручки, среднего чека, динамики и сегментов (сеть/город/аптека/смена/кассир).
3. **Правила аномалий:** просадки выручки, всплески возвратов, нулевые продажи ключевых SKU, необычные скидки, смещение пиков продаж.
4. **Журнал инцидентов + алерты:** карточка отклонения, причина, рекомендация, статус; ежедневный дайджест.
5. **Прототип панели:** дешборды + чат GPT с подписью «ГК “Садыхан”» слева, ответы по загруженным данным и журналу.
6. **Рефайн LLM-агента:** поиск контекста, генерация гипотез, объяснения причин, предложения действий.

## Нефункциональные требования
- Безопасность доступа к данным и журналу отклонений.
- Масштабируемость витрины и алгоритмов аномалий по мере подключения точек/городов.
- Прозрачность: трассировка исходных данных для объяснений.
- Эксплуатация: мониторинг пайплайнов, SLA по обновлению данных и доставке алертов.

## Технологический ориентир
- Веб-стек: Python/Flask или FastAPI для API, SPA-фреймворк для панели.
- Хранилище: реляционная БД/витрина (PostgreSQL/ClickHouse/BigQuery) для чеков и агрегатов.
- Аналитика/ML: правила + статистические модели; последующее расширение до прогнозов и план/факт.
- LLM: GPT-оркестрация с Retrieval (векторный индекс или поиск по витрине и журналу), управление промптами и безопасностью.
- Интеграции: боты/вебхуки для уведомлений, SSO/роль-менеджмент для панели.
